# 2026-10-27 全仓维护性审查

## 范围与方法

本轮覆盖 `lib` 的 214 个手写 Dart 文件（375 个类），并检查测试、开发工具、应用组装和 CI 中的引用；原生宿主与 Windows 插件补丁进行静态阅读。生成代码、SDK 和第三方实现不按项目命名规则手工重写。

检查重点是实际维护路径：从界面操作能否找到状态入口、数据契约与具体实现；同一流程是否需要经过无独立价值的转发；数据模型是否混入外部映射；连接、异步任务和界面通知是否有明确收尾。类型和依赖清单用于全量定位，修改点及数据库、扫描、偏好、播放收尾等关键路径按实现复查。此记录不是所有行为均无缺陷的保证。

## 检查结果与处理

| 范围 | 结论与处理 |
| --- | --- |
| 应用启动、路由与退出 | 保留 `ApplicationDependencies` 的具体实现组装和退出协调入口；共享数据库由应用持有，播放器不关闭它 |
| 数据库与数据仓库 | 删除 `MediaDatabaseStore` 包装层；连接、初始化、公共 CRUD 和事务集中到 [AppDatabase](../../lib/core/data/database/app_database.dart)。各功能 Repository 直接接收同一实例，不再通过 `.database.database` 访问 SQL；关闭操作保持幂等 |
| 目录查询与展示 | 保留按 SQL 筛选、排序、分页和批量读取的实现；Mapper 只做内存转换，不恢复逐项补查；DO、业务模型与 VO 边界保留 |
| 文件浏览与来源 | 保留统一的来源操作入口、协议注册和连接释放；保存 / 删除后的失效回调由应用组装，界面不直接串联多个 Provider |
| 扫描与元数据 | 保留完整扫描后才能清理、分批写入和失败保留原关联的规则；简单搜索计划工厂并入 `ScrapeSearchPlan.forCandidate`，减少一个类、文件与构造依赖 |
| 播放会话与界面 | 会话持有引擎和播放目标；窗口、字幕、进度与浮层各自拥有实际资源。不为缩短行数拆散同一菜单或同一解析流程 |
| 设置、主题与语言 | 修复普通设置忽略存储插件 false 返回值；迟到的主题 / 语言读取不覆盖用户修改；销毁后不通知界面、不应用迟到配置，已接受保存继续排空 |
| 首页及共享 UI | 保留单向消费媒体库展示入口；共享图片组件承接缓存适配，不在页面引入具体数据实现；没有新增 UI 管理层 |
| 原生宿主 | 检查视图 ID 路由、窗口操作和系统退出交接；补充自有 Swift / C++ 入口的中文职责说明，没有修改原生行为或第三方补丁 |
| 工具、测试与文档 | 同步删除类型的引用和构造方式，更新维护地图与编码规则；保留能够拦截反向依赖、模型混用和循环依赖的架构检查 |

删掉包装层并不意味着把所有 SQL 放入一个类：共享连接及公共读写在 `AppDatabase`，复杂目录投影和特定流程数据能力留在对应 Repository。新增名称或文件应有独立的职责、边界或资源所有权，不能只为了形式上的分层。
