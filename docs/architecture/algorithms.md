# 规则、查询策略与算法

本文说明文件解析、元数据匹配、库查询及任务调度规则。视频解码、音画同步、硬解和字幕渲染由播放后端负责。

## 扫描与幂等索引

扫描清理采用集合差：原有路径减去本次发现路径；读取失败或退出中断时禁止删除。`(sourceId, path)` 唯一约束保证重复扫描幂等，入库与字段更新步骤见 [媒体流水线](media-pipeline.md#阶段-1扫描与入库)。

深度优先遍历的工作量随目录项数量增长，递归栈随目录深度增长。虽然文件以异步流产出，控制器仍保存已知 / 已扫描路径集合，内存并非常数；超大目录与异常目录循环需单独验证。

## 文件名解析

[MediaFilenameParser](../../lib/features/library/sync/domain/media_filename_parser.dart) 按优先级提取季集、显式 ID 和技术信息，并清洗标题；完整规则与示例集中在 [媒体流水线](media-pipeline.md#阶段-2文件名解析)。解析属性不等于成功匹配 TMDB。

## 刮削计划与有界并发

[ScrapeSearchPlan.forCandidate](../../lib/features/library/metadata/domain/scrape_search_plan.dart) 最多构造两次标题搜索：完整清洗标题 + 年份，然后相同标题不带年份；无年份时不重复请求。`MetadataMatcher` 优先处理显式 / 已确认 ID，查询结果采用 TMDB 返回的第一个有效对象，项目没有编辑距离或自研模糊评分。

剧集按显式 / 确认 ID 或规范化标题分组，复用剧集 / 季详情请求；不同文件版本仍保留为独立文件。`MetadataScraper` 分电影阶段与剧集分组阶段执行，每阶段最多 5 个异步 worker，领取下一项后等待请求完成。worker 在同一 isolate 中限制 I/O 并发。

请求错误与无匹配分开处理；失败不触发标题回退或清除原关联，当前没有自动重试 / 退避。具体传播和季级隔离见 [媒体流水线](media-pipeline.md#请求失败与未匹配)。

## 本地搜索评分

[normalizeLibrarySearchText](../../lib/core/domain/media/library_search_text.dart) 将文本小写并移除规定的空格 / 分隔符；它不是完整的 Unicode NFKC、拼音或繁简转换。

[LibraryCatalogRepositoryImpl](../../lib/features/library/catalog/data/library_catalog_repository_impl.dart) 在 SQL 中对标题 / 原标题取两者评分的最大值：

| 匹配 | 标题得分 | 原标题得分 |
| --- | --- | --- |
| 完全相等 | 120 | 110 |
| 前缀匹配 | 100 | 90 |
| 包含匹配 | 80 | 70 |
| 无匹配 | 0 | 0 |

例如搜索 `example`：标题 `Example` 优先于 `Example Two`，后者优先于 `My Example`。同分用稳定业务键排序；最近添加列表另优先按添加时间排序。使用 `instr` 与规范化函数，不是全文检索或索引支持的模糊搜索；性能按实际数据规模验证。

## 收藏、续播与播放队列

- 收藏查询用 `ROW_NUMBER() OVER (PARTITION BY group_key ...)` 先选每标题代表，再应用排序与 LIMIT，避免多个版本挤占列表。
- 继续观看查询先选每标题最近活动；剧集未完成则续播，已完成则找后续未完成的单集，跳过同集其他版本；没有后续目标的剧集不进入继续观看。
- [EpisodePlaybackTargetResolver](../../lib/core/domain/media/episode_playback_target_resolver.dart) 在剧集播放入口按季 / 集 / 路径排序选择目标；显式播放允许从首个未完成项开始或全部完成后重播。
- 首页继续观看在 SQL 中执行；查询测试用 [LibraryContinueWatchingReference](../../test/support/library_continue_watching_reference.dart) 比较结果，参考实现仅用于测试。
- 普通标题、收藏与续播仅为 SQL 已选出的当前页批量补齐元数据：电影 / 剧集 ID 分开去重，每批最多 400 个，按类型和 ID 回填并保持原 SQL 顺序。卡片组装不执行数据库查询，不跨刷新缓存元数据；表变更通过订阅触发更新。100 条已匹配的混合卡片需要 1 次列表查询 + 2 次元数据查询，只有一种类型时共 2 次，无关联元数据时仅 1 次；扩展页按 400 个 ID 分批增加查询。
- [PlaybackQueue](../../lib/features/playback/domain/playback_queue.dart) 按 `sourceId:path` 用集合去重并保留输入顺序；上一项 / 下一项通过当前索引和偏移选择。剧集的输入顺序来自库查询。

领域续播选择包含排序，通常为 O(n log n)；队列去重为期望 O(n)，索引选项为 O(1)。SQL 窗口函数与关联子查询的实际成本取决于数据分布、索引和执行计划，不能直接套用领域实现的复杂度。

## 首页内容推荐与每日精选

推荐使用本地类型特征的内容推荐与 MMR（最大边际相关性）重排，不需要联网或多用户数据。
[LibraryRecommendation](../../lib/features/library/catalog/domain/library_recommendation.dart) 是纯领域规则；
[LibraryRecommendationService](../../lib/features/library/catalog/application/library_recommendation_service.dart) 管理每日选择及订阅资源，
`MediaLibraryProvider.heroItems` 发布只读结果，首页横幅只负责展示与切换。旧的单条日期取模查询与最近添加补位已移除。

### 候选与偏好

- `LibraryCatalogRepository.watchRecommendationCandidates()` 读取整个库中有关联电影 / 单集文件且有元数据的标题，按类型与 TMDB ID 聚合。元数据存在但没有关联文件、未匹配文件不参与。这里的可用性表示有本地文件索引，不代表已实时检查磁盘或远程来源在线。
- 收藏、已开始、已看完分别取任一关联文件；添加时间取最早，观看时间取最近。多版本或很多集不会把一个标题重复计入偏好。剧集的“看完”信号表示至少完成一集，不推断整剧完成。
- SQL 聚合后复用现有批量元数据入口，每类型每批最多 400 个 ID，不逐标题查询。推荐需读取全库标题特征，内存随标题数量增长；与普通分页列表的有限投影不同。
- 类型标签去空白、转小写、去重后形成二值向量并归一化；收藏权重为 3，看完权重为 1，后者按最近观看时间以 90 天半衰期衰减。没有观看时间的完成信号不衰减。汇总所有标题的加权向量后再次归一化，用余弦相似度计算个人偏好相关性。

### 评分与多样性

候选基础分为 `0.60 × 偏好相似度 + 0.15 × 新鲜度 + 0.10 × 展示完整度 + 0.15 × 每日探索值`：

- 新鲜度按最早添加时间以 30 天半衰期衰减；未来时间按当天处理。
- 展示完整度由非空横幅地址（0.7）和简介（0.3）组成，不发起图片探测请求；图片不全的内容仍可参与。
- 探索值由本地日历日期、媒体类型及 TMDB ID 的显式稳定哈希得到，不使用进程内 `hashCode`。相同日期与输入在重启或输入重排后结果一致。

优先从从未开始的标题中选取，再以已开始的标题补足，最多五项；每轮选择
`0.7 × 基础分 − 0.3 × 与已选标题的最大类型相似度` 最高的候选。分数相同时按稳定身份排序。
无偏好历史时，相关性为零，以新鲜度、展示完整度、探索值及多样性完成冷启动；小库允许补入已看内容。
类型向量稀疏运算之外，选择五项采用逐轮线性扫描，不构建全库两两相似度矩阵。

这些权重是可解释的初始启发式，没有经过用户反馈数据训练或效果实验。当前仅使用类型标签，不使用评分、演员、简介语义向量；不同语言的类型标签也不做语义合并。

### 每日刷新与资源

每个用例订阅缓存当前候选快照和所选标题身份。同一本地日历日，收藏 / 进度变化更新快照但不重排；所选标题的元数据仍会更新。
候选标题增删或跨日时使用最新快照重新选取；跨日由下一次本地午夜计时器触发，数据库事件也会核对日期。
查询失败沿流报告，跨日不会将失败前的旧快照当作恢复结果。取消订阅或上游结束时释放计时器及查询监听。
横幅同标题快照刷新不重置二十秒轮播计时。

每日结果不额外写入数据库；重启时按最新数据重新计算，因此同日观看 / 收藏数据已经变化时，重启后的结果可能变化。
尚无曝光历史、长期重复抑制或推荐准确率基线；这些不属于当前实现保证。

## 进度与窗口任务顺序

[PlaybackProgressWriter](../../lib/features/playback/application/playback_progress_writer.dart) 按接受顺序串行写入，防止旧快照覆盖新位置。失败返回调用方，但不阻断后续队列；关闭前等待已接受写入。保存周期、位移阈值及续播规则见 [播放](playback.md#进度与续播)。

`PlayerWindowCoordinator` 同样串行处理创建 / 替换；退出时拒绝新请求并收尾已接受操作。超时只保证有界结束，不保证最后进度落库，详见 [播放生命周期](playback.md#生命周期与退出)。
