# 0006 媒体服务器接入：Emby 优先，独立于文件系统媒体源

- **Status**: Accepted
- **Date**: 2026-10-08
- **Related**: [多窗口](0001-multi-window-strategy.md)、[播放引擎](0002-playback-engine.md)、[持久化](0003-persistence-migration.md)、[SMB](0005-smb-playback-path.md)

本文是已接受的方向与实施计划，尚未实现；接口名称为规划，不能作为现有 API 使用。完成度见 [实施状态](../status.md)。

## Context（背景与约束）

本地、WebDAV 与 SMB 按路径浏览、扫描并建立本地索引。媒体服务器提供自己的条目、元数据、用户观看状态及播放会话，不能等同于文件目录。

Emby 需要先协商直放、直流或转码，再上报播放状态。依据：[认证](https://dev.emby.media/doc/restapi/User-Authentication.html)、[浏览](https://dev.emby.media/doc/restapi/Browsing-the-Library.html)、[PlaybackInfo](https://dev.emby.media/reference/RestAPI/MediaInfoService/getItemsByIdPlaybackinfo.html)、[会话上报](https://dev.emby.media/doc/restapi/Playback-Check-ins.html)。[Jellyfin](https://jellyfin.org/docs/general/clients/) 与 Emby 相似但仍需独立验证；[Plex](https://developer.plex.tv/pms/) 有独立的认证与媒体库 API。

## Decision（决策）

**建立独立的媒体服务器接入层，先交付 Emby；不作为 StorageAdapter / StorageSource 的一种实现。**

1. 账户、连接、目录浏览与远端播放会话独立于文件扫描。服务器条目不伪装成 `MediaFile`，不进入本地 TMDB 刮削或本地进度写入。
2. 条目身份包含账户 ID、服务类型、服务端 ID 与条目 ID，隔离不同用户 / 服务器；不以文件路径为唯一键。
3. 窗口请求只传非敏感标识，由播放侧读取凭据并协商会话。密码仅用于首次认证，之后使用可撤销令牌；敏感值与普通配置分离，不进入窗口参数、日志或可见 URL。
4. 远端会话负责开始、进度、暂停 / 恢复及停止上报，不塞进只返回静态 `PlaybackTarget` 的接口。本地播放保留现有链路。
5. Emby 稳定后再实现 Jellyfin；Plex 单独评估，不同时交付一套假定通用的多厂商 API。

## 实现计划

| 阶段 | 主要工作 | 交付边界 |
| --- | --- | --- |
| 0：真实 API 验证 | 确定 Emby 版本范围，验证登录、令牌续用 / 撤销、分页 / 详情 / 图片 / 观看状态、三种播放路径及会话上报 | 记录请求头、轨道、seek / Range、断网与令牌失效行为；提交脱敏响应样例，排除凭据与真实服务器地址 |
| 1：模型与存储 | 建立账户、连接、条目投影、播放会话契约及注册表，分离凭据存储 | 账户含类型、显示名、URL、服务端 / 用户 ID、启用状态及能力 / 版本；条目保留来源、媒体源 ID 和播放状态；定义分页、认证、不可用媒体及拒绝播放错误，持久化遵循 ADR 0003 |
| 2：Emby 浏览 | 添加 / 编辑 / 删除服务器、测试连接、登录 / 登出；浏览有权限的电影、剧集、季集及视频，提供分页、搜索、详情与海报 / 背景图 | 支持多服务器；本地与服务器媒体库入口分开；先交付只读浏览 |
| 3：播放与进度 | 按下方会话规则接入 libmpv、续播、状态上报与停止回收 | 只写远端会话和进度；服务器转码 / 不可 seek 等限制由 UI 明示，外挂字幕、倍速与硬解逐项验证 |
| 4：后续适配 | 公共契约补齐模拟服务端测试，再验证 Jellyfin 差异；按需求评估 Plex | 厂商认证、令牌、条目键及时间线留在各自适配器；统一搜索 / 续看、能力探测、缓存、重试与实时更新另行评估 |

### 播放会话规则

- 通过 `PlaybackInfo` 取得来源、URL 与请求头，再交给 libmpv；不自行拼接文件路径。会话保留 `PlaySessionId`、媒体源 ID 与服务器条目 ID，并验证轨道索引映射。
- 开始时上报；约每 10 秒及状态变化时报告位置、暂停状态、音轨与字幕轨；结束、切换条目或关闭窗口时发送停止事件并释放服务端资源。
- 续播与已观看状态以 Emby 为准。同步失败需提示，但不中断当前播放，也不回写本地文件进度。

### 首期范围与验收

首期不包含服务器收藏写入、播放列表编辑、实时推送、远程文件管理、Live TV、音乐库、远程控制、服务器管理、内容下载或本地 / 远端库自动合并；Plex 不在首期范围。

| 场景 | 通过标准 |
| --- | --- |
| 登录与浏览 | 可配置多个 Emby 服务器、登录、选择媒体库、分页搜索与查看详情；同名条目不串数据 |
| 播放与续播 | 电影 / 剧集按协商结果播放，读取服务端续播并上报进度 / 停止；不触发本地扫描、刮削或进度写回 |
| 失败与恢复 | 离线或令牌撤销有可操作提示，重试 / 重登可恢复；同步失败不打断播放 |
| 回归与隐私 | 覆盖分页、令牌过期、URL / 请求头解析、进度及停止回收；日志 / 诊断不含密码、令牌或完整敏感 URL |

## Consequences（后果）

- **收益**：元数据、观看状态和播放协商的归属明确；新增厂商不改变文件系统接口。
- **代价**：增加账户、API 适配、会话与异步错误处理；需应对服务端版本、权限及转码差异。

## Alternatives（备选与否决理由）

| 方案 | 否决原因 |
| --- | --- |
| 当作 WebDAV / SMB 文件源 | 丢失条目身份、元数据、转码协商与进度会话 |
| 全部同步为本地 MediaFile 后刮削 | 重复存储，路径与观看状态所有权混乱 |
| 一开始覆盖 Emby / Jellyfin / Plex | 差异未经验证，容易把厂商分支带入公共接口 |
| 只取 URL，不上报会话 | 服务器无法正确维护当前设备、续播与观看状态 |

## Revisit trigger（重估触发条件）

1. API 验证发现 Emby 版本 / 权限使首期目标不可行。
2. 厂商差异迫使公共接口出现大量专属字段。
3. 产品要求统一首页 / 搜索、收藏、观看状态或 TMDB 元数据。
4. ADR 0003 的持久化方向变化，需要调整账户与令牌存储计划。
