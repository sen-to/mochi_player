# 0006 媒体服务器接入：以 Emby 为首个适配器，独立于文件系统媒体源

- **Status**: Accepted
- **Date**: 2026-10-08
- **Related**: [0001 多窗口策略](0001-multi-window-strategy.md)、[0002 播放引擎](0002-playback-engine.md)、[0003 持久化迁移](0003-persistence-migration.md)、[0005 SMB 播放路径](0005-smb-playback-path.md)

## Context（背景与约束）

当前应用把本地目录、WebDAV 与 SMB 统一建模为文件系统媒体源：连接后列目录，再按 `sourceId + path` 扫描文件、写入本地媒体库，最后由 `PlaybackTargetResolver` 解析成 URL 与请求头。这个模型适用于「文件在哪」，不覆盖媒体服务器提供的远程媒体库、账号级观看状态与播放会话。

Emby 的 API 分别提供用户媒体库视图与项目列表、播放信息解析，以及播放开始 / 进度 / 停止上报。`PlaybackInfo` 可能给出直放、直流或转码的来源、URL、请求头和播放会话 ID，因此播放并非总是简单地把媒体路径交给本地解析器。相关 API： [认证](https://dev.emby.media/doc/restapi/User-Authentication.html)、[媒体库浏览](https://dev.emby.media/doc/restapi/Browsing-the-Library.html)、[PlaybackInfo](https://dev.emby.media/reference/RestAPI/MediaInfoService/getItemsByIdPlaybackinfo.html)、[播放会话上报](https://dev.emby.media/doc/restapi/Playback-Check-ins.html)。

兼容范围也不能只靠一套假定通用的 REST 路径：Plex 采用自己的认证与媒体库 API；Jellyfin 与 Emby 的接口相似，但仍需独立实测并维护适配器。参考：[Plex Media Server API](https://developer.plex.tv/pms/)、[Jellyfin 客户端文档](https://jellyfin.org/docs/general/clients/)。

## Decision（决策）

**支持 Emby 等媒体服务器；首个可交付适配器为 Emby，并以独立的媒体服务器接入层承载后续适配器。媒体服务器不作为 `StorageProvider` 或普通 `StorageSource` 的一种实现。**

具体规则：

1. 文件系统媒体源继续负责路径浏览、扫描和本地索引；媒体服务器通过单独的账户、连接、目录浏览与播放会话接口接入。
2. 首期由 Emby 提供媒体元数据、用户观看状态和播放进度。本地 TMDB 刮削与本地文件进度写入不覆盖服务器数据，也不把远端条目伪装成本地 `MediaFile`。
3. 远程条目以命名空间隔离的身份引用（账户 ID + 媒体服务器类型 + 服务端 ID + 条目 ID），避免同一服务器的不同用户共享观看状态，不使用文件路径作为唯一键。
4. 播放器窗口请求只传账户 ID、服务器 ID、条目 ID 等非敏感标识。播放器窗口从凭据存储取令牌，再通过适配器取得播放信息并创建播放会话；令牌不得放进窗口参数、日志或可见 URL。
5. 远端播放会话负责开始、周期进度、暂停 / 恢复状态与停止上报；本地媒体继续使用现有进度写入链路。播放会话不强行塞进只返回静态 `PlaybackTarget` 的接口。
6. Emby 稳定后再实现 Jellyfin 适配器并执行共同契约验证；Plex 作为后续独立适配器评估，不把首期范围扩成多服务器并行交付。

## 实现计划

### 阶段 0：API 可行性验证

- 选定受支持的 Emby Server 版本范围，验证手动填写服务器地址、用户登录与令牌续用 / 撤销流程。
- 用真实服务端验证用户媒体库视图、分页列表、条目详情、图片与用户播放状态读取。
- 分别验证 `PlaybackInfo` 返回的直放、直流和转码路径；记录 URL、必需请求头、音轨 / 字幕轨、seek 与 Range 行为。
- 验证播放开始、约每 10 秒进度更新、交互后更新、播放停止的会话上报，以及断网、令牌失效时的行为。
- 产出少量脱敏响应样例供解析器单元测试使用；不要将用户凭据或真实服务器地址提交到仓库。

### 阶段 1：领域与持久化边界

- 新增媒体服务器账户配置：服务类型、显示名、服务器 URL、服务端 ID、用户 ID、启用状态与能力 / 版本信息。
- 新增凭据存储接口，将密码仅用于首次认证，之后保存可撤销令牌；敏感值与普通账户配置分离。具体数据库实现遵循届时已接受的持久化方案（见 [0003](0003-persistence-migration.md)）。
- 建立独立的 `MediaServerProvider` / 连接 / 播放会话契约及注册表；定义分页、认证错误、不可用媒体、服务端拒绝播放等可解释错误。
- 定义服务端条目的稳定引用与 UI 所需的媒体投影；条目映射保留服务端 ID、媒体源 ID、播放状态和来源归属。

### 阶段 2：Emby 连接与媒体库浏览

- 提供添加 / 编辑 / 删除服务端、测试连接、登录和登出的完整流程；同一用户可配置多个服务器。
- 展示用户有权访问的媒体库，支持分页加载电影、剧集、季、集和视频条目，并支持基本搜索、详情、海报与背景图。
- 浏览阶段先交付只读目录与详情；播放阶段只写播放会话和进度，不做库扫描、TMDB 匹配、收藏写入、播放列表编辑、实时更新推送或远程文件管理。
- 明确区分「本地媒体库」和「服务器媒体库」入口，避免把远端记录误认为已经落入本地 Isar / SQLite。

### 阶段 3：播放与服务器进度

- 通过 Emby `PlaybackInfo` 请求协商播放来源，再按响应提供的 URL 与请求头交给 libmpv；将 `PlaySessionId`、媒体源 ID、服务器条目 ID 保留在会话对象中。
- 以适配器返回的播放信息为准选择直放、直流或转码，不自行拼接媒体文件路径；轨道索引映射需验证与 libmpv 轨道编号一致。
- 播放开始时上报会话；播放期间定时及状态变化时上报位置、暂停状态、音轨和字幕轨；结束、切换条目或窗口关闭时发送停止并释放服务端资源。
- 续播位置与已观看状态读取 / 写回 Emby。上报失败不应中断当前播放；提示同步失败，也不把服务器条目写入本地播放进度。
- 用户主动添加的外挂字幕、倍速、硬件解码等本地播放器能力按现有引擎能力逐项验证；服务器转码限制、不可 seek 流等情况要由 UI 明示。

### 阶段 4：第二种服务器与体验完善

- 对 Emby 适配器形成的公共契约补齐模拟服务端测试后，独立实现 Jellyfin 适配器并验证认证、分页、播放协商和进度上报差异。
- 根据实际需求评估 Plex；其认证流程、令牌生命周期、项目键和播放时间线均由 Plex 适配器封装，不泄漏到公共领域层。
- 后续再评估与本地媒体库的统一搜索 / 继续观看视图、服务端能力探测、封面缓存、网络重试和实时库更新。

## 首期验收条件

- 用户可以添加 Emby 服务器、完成登录、选择媒体库、浏览详情并播放电影和剧集。
- 播放能按服务端协商结果运行；可以读取服务端续播位置，并将播放进度与停止状态报告回服务端。
- 服务器离线或令牌被撤销时，界面给出可操作错误；重试 / 重新登录后可继续使用。
- 多服务器同名条目不会串数据；服务器条目不进入本地文件扫描、TMDB 刮削或本地媒体进度写回。
- 测试覆盖分页、令牌过期、播放 URL / 请求头解析、进度上报、停止回收；日志和崩溃诊断中不出现密码、令牌或完整敏感 URL。

## Consequences（后果）

- **正面**：媒体服务器保留自己的元数据与观看状态；播放协商和会话回报有明确归属；新增服务器时不需要把媒体目录 API 混入文件系统接口。
- **负面**：新增账户管理、服务端 API 适配、会话生命周期和异步错误处理；服务端能力、版本、权限和转码策略会造成行为差异。
- **边界**：首期不承诺 Plex、Live TV、音乐库、远程控制、服务器管理、服务端内容下载或媒体服务器与本地 TMDB 库的自动合并。

## Alternatives（备选与否决理由）

| 备选 | 评价 | 结论 |
| --- | --- | --- |
| 把 Emby 当作 WebDAV / SMB 文件源 | 会丢失媒体服务器的条目 ID、元数据、转码协商和进度会话 | 否决 |
| 同步服务器全部条目进本地 `MediaFile` 并重新刮削 | 产生重复数据，服务器条目不是本地路径，进度所有权也会混乱 | 否决 |
| 先做覆盖 Emby / Jellyfin / Plex 的“通用 API” | 认证、条目标识和播放会话存在差异，过早抽象会暴露厂商条件分支 | 否决；先抽象实际共性并分别验证 |
| 只取一个播放 URL，不实现会话回报 | 能开始播放，但服务器无法正确记录当前设备、续播位置和观看状态 | 否决 |

## Revisit trigger（重估触发条件）

1. 第一阶段验证发现 Emby Server 的版本或权限限制使本 ADR 的首期功能不可行；
2. Jellyfin / Plex 的真实 API 差异迫使公共媒体服务器接口出现大量厂商专属字段；
3. 本地优先库与服务端库需要合并为唯一首页 / 搜索结果，且用户明确要求统一收藏、观看状态或 TMDB 元数据；
4. [0003 持久化迁移](0003-persistence-migration.md)改变数据层实施时序，需要重排账户与令牌存储阶段。
