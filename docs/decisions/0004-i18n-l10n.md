# 0004 国际化与本地化：官方 gen-l10n + ARB（英文模板 / 中文译文）

- **Status**: Accepted
- **Date**: 2026-10-05
- **Related**: —

## Context（背景与约束）

术语先厘清（两者是层次关系，不是二选一）：

- **i18n = internationalization**：让软件**有能力**被本地化的架构与机制（文案抽离、locale 感知的日期/数字/复数/排序）；
- **l10n = localization**：针对**某个具体 locale** 的落地产物（一份译文、一套格式）。

Flutter 官方工具链的命名使用 l10n：`flutter gen-l10n`、`l10n.yaml`、生成的 `AppLocalizations`；`flutter_localizations` 与 `intl` 属于 i18n 能力层。

当前状态：

- 应用界面文案**硬编码**在 widget 中，全部为简体中文；
- `pubspec.yaml` 中**没有** `flutter_localizations`、没有 `generate: true`；仓库**没有** `l10n.yaml`；
- `MaterialApp.router`（[main.dart:89-104](../../lib/main.dart#L89-L104)）**未配置** `localizationsDelegates` / `supportedLocales`，因此 Material 内建文案（文本选择菜单、日期选择、语义标签等）实际以英文呈现——这与「界面仅提供简体中文」的现状不一致；
- 已存在为此绕行的手写实现：[app_text_context_menu.dart](../../lib/core/ui/components/input/internal/app_text_context_menu.dart)；
- `intl` 已被直接使用（[file_browser_entry_display.dart:2](../../lib/features/library/presentation/widgets/file_browser_entry_display.dart#L2) 的日期格式化）；
- 平台侧 `Info.plist` 已声明 `CFBundleLocalizations: [en, zh-Hans]`。

约束：界面语言策略是「首版跟随系统」，应用内语言切换不在本次范围内；文案必须支持 ICU 占位符与复数规则。

## Decision（决策）

**采用 Flutter 官方 gen-l10n 工具链，ARB 资源放在 `lib/l10n/`，以 `app_en.arb` 为模板、`app_zh.arb` 为译文。**

必须遵守的规则：

1. 新增或修改用户可见文案**必须**走 ARB 资源，不得在 widget 中硬编码；评审时以此为准。
2. `MaterialApp` **必须**配置 `localizationsDelegates`（`AppLocalizations.delegate` + 全局 Material/Widgets/Cupertino 委托）与 `supportedLocales`，使系统内建文案与业务文案语言一致。
3. locale 敏感的格式化（日期、数字）**必须**经由 `intl` 并显式传入当前 locale，不得依赖默认 locale。
4. ARB 模板语言固定为英文：新文案先写 `app_en.arb`，再补 `app_zh.arb`；缺失译文在评审中视为未完成。
5. 生成物不提交入库，由构建与 CI 生成（与代码生成物 `*.g.dart` 的策略不同，理由是本地化文件变动频繁且无跨平台二进制语义）。

## Consequences（后果）

- **正面**
  - 立即修复「中文界面 + 英文系统文案」的不一致；
  - 新增语言只需新增 ARB 文件，不再改动业务代码；
  - 复数、占位符、性别等规则由 ICU 表达，避免手写字符串拼接；
  - `intl` 已在依赖中，不增加新的第三方包。
- **负面**
  - 所有文案访问需要 `context`（`AppLocalizations.of(context)`），在无 context 的场景（如后台任务、纯 Dart 服务）需改为返回文案键或结构化错误码，这会推动部分错误提示语义的调整；
  - 现有 `AppMessage` / 错误字符串分散在各层，抽取是一次跨模块改动，需要分期进行；
  - 引入 `generate: true` 后，首次构建与 CI 需要执行生成步骤。
- **跟进**
  1. 接线阶段：`pubspec.yaml` 增加 `flutter_localizations` 与 `generate: true`，新建 `l10n.yaml` 与 `lib/l10n/app_en.arb`、`app_zh.arb`，在 `MaterialApp.router` 配置委托与 `supportedLocales`（此阶段即可修掉英文系统文案）；
  2. 抽取阶段：按 `settings → library → playback → app shell` 顺序抽取硬编码文案；
  3. 收尾：`app_text_context_menu.dart` 改为复用本地化文案，保留自定义样式。

配置约定（实施时以官方文档为准）：

```yaml
# l10n.yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
nullable-getter: false
```

## Alternatives（备选与否决理由）

| 备选 | 否决理由 |
| --- | --- |
| 自建 `Map<String, String>` 文案表 | 需要自己实现 locale 解析、复数、占位符与回退逻辑，且无法与 Material 内建文案打通 |
| 只补 `localizationsDelegates` 不抽文案 | 能修掉系统文案，但业务文案仍硬编码，后续抽取成本只会更高 |
| 第三方方案（如 `slang`、`easy_localization`） | 能力与官方方案重叠，且引入额外依赖与生成器；官方方案零额外依赖 |
| 以中文为模板（`app_zh.arb` 作 template） | 本可接受，但英文模板符合 gen-l10n 默认约定、ICU 复数表达更完整，也更利于外部贡献者；本项目已存在英文需求（系统文案） |

## Revisit trigger（重估触发条件）

满足任一条即重新评估：

1. 需要第三种语言，或需要应用内语言切换（此时要额外设计语言偏好持久化与热切换范围）；
2. 文案需求超出 ARB 表达力（例如需要按语言切换整站文案风格、或需要翻译平台对接流程）；
3. Flutter 官方本地化方案发生重大变更（如 gen-l10n 被替代）。
