# 0004 国际化与本地化：官方 gen-l10n + ARB（英文模板 / 中文译文）

- **Status**: Accepted
- **Date**: 2026-10-12（初稿 2026-10-05）
- **Related**: [0001 多窗口策略](0001-multi-window-strategy.md)

## Context（背景与约束）

术语先厘清（两者是层次关系，不是二选一）：

- **i18n = internationalization**：让软件**有能力**被本地化的架构与机制（文案抽离、locale 感知的日期/数字/复数/排序）；
- **l10n = localization**：针对**某个具体 locale** 的落地产物（一份译文、一套格式）。

Flutter 官方工具链的命名使用 l10n：`flutter gen-l10n`、`l10n.yaml`、生成的 `AppLocalizations`；`flutter_localizations` 与 `intl` 属于 i18n 能力层。

实施前的状态：

- 本轮实施前，界面文案硬编码为简体中文，设置页仅预留语言入口；本轮状态见下方「实施阶段与验收」。
- `pubspec.yaml` 中**没有** `flutter_localizations`、没有 `generate: true`；仓库**没有** `l10n.yaml`；
- 主窗口 `MaterialApp.router`（[main.dart](../../lib/main.dart)）与播放器窗口的 [MaterialApp](../../lib/features/playback/presentation/player_window_app.dart) 均**未配置** `localizationsDelegates` / `supportedLocales`，因此 Material 内建文案（文本选择菜单、日期选择、语义标签等）实际以英文呈现——这与「界面仅提供简体中文」的现状不一致；
- 已存在为此绕行的手写实现：[app_text_context_menu.dart](../../lib/core/ui/components/input/internal/app_text_context_menu.dart)；
- `intl` 已被直接使用（[file_browser_entry_display.dart](../../lib/features/library/presentation/widgets/file_browser_entry_display.dart) 的日期格式化）；
- 平台侧 `Info.plist` 已声明 `CFBundleLocalizations: [en, zh-Hans]`。

- 设置页已经预留「应用语言」选择入口，但目前只有 `zh-CN` 选项、空回调，没有持久化或窗口语言状态；入口预留不等于切换功能已接通。

2026-10-12 用户明确要求应用内语言切换，取代初稿「首版只跟随系统」的范围。首版提供「跟随系统 / 简体中文 / English」，支持 ICU 占位符与复数规则。下文为决策与实施要求；接线、偏好与文案抽取本轮已完成，运行时验收边界见下方。

## Decision（决策）

**采用 Flutter 官方 gen-l10n 工具链，ARB 资源放在 `lib/l10n/`，以 `app_en.arb` 为模板、`app_zh.arb` 为简体中文译文。提供可持久化的应用内语言偏好，主窗口与播放器即时保持一致。**

必须遵守的规则：

1. 新增或修改用户可见文案**必须**走 ARB 资源，不得在 widget 中硬编码；评审时以此为准。
2. 主窗口与播放器窗口的 `MaterialApp` **必须**配置 `localizationsDelegates`（`AppLocalizations.delegate` + 全局 Material/Widgets/Cupertino 委托）、`supportedLocales` 与语言偏好对应的 `locale`，使 Flutter 内建文案与业务文案语言一致。
3. locale 敏感的格式化（日期、数字）**必须**经由 `intl` 并显式传入当前 locale，不得依赖默认 locale。
4. ARB 模板语言固定为英文：新文案先写 `app_en.arb`，再补 `app_zh.arb`；缺失译文在评审中视为未完成。
5. 生成物不提交入库，统一输出到 `lib/l10n/generated/` 并忽略此目录；ARB、`l10n.yaml` 与调用代码必须提交。通过项目包路径导入生成文件，不使用已废弃的 `package:flutter_gen` 或 synthetic package。
6. 不把 `BuildContext`、生成的本地化对象或已翻译文案传入数据库、网络与纯 Dart 服务。用户可见的服务错误 / 后台状态使用类型明确的错误码和参数，在展示层解析为本地化文案。底层诊断日志不要求翻译；不能直接把原始异常当用户文案。

### 语言偏好与双窗口同步

- 默认偏好为 `system`，用户可选 `system`、`zh`、`en`。未保存或保存值非法时回到 `system`，不用显示名称作存储键；`zh-CN` 只是当前占位控件的值，不作为已存在的持久化格式。
- 与应用设置一样使用 SharedPreferences 持久化，保存用户选择，而非当时解析出的系统语言。切回「跟随系统」后，两个窗口都重新根据系统 locale 解析，系统语言变化也应在该模式下响应。
- 首版支持 `en`、`zh`：中文 locale 统一使用简体中文资源；不提供繁体中文独立译文。系统语言列表优先匹配支持语言，无匹配时回退英文，明确以英文为默认回退，不依赖偶然的列表排序。
- 2026-10-13 官方单引擎多视图迁移后，两个视图共享同一个 `AppLocaleController`，Provider 通知直接重建各自的 `MaterialApp`；移除窗口语言 RPC、revision、快照与子窗口偏好加载。
- 偏好按接受顺序保存，退出时拒绝新变更并等待已接受写入；失败后可重试相同选择。复用 / 替换播放器不重置语言，也不重新读取独立缓存。
- 切换语言不重建播放器会话、不重新打开媒体，也不重置主题、扫描、字幕选择或播放进度。挂起的后台操作返回后按展示时的语言生成提示。
- 界面语言、媒体文件名 / 用户输入、TMDB 元数据语言、字幕语言优先级是不同设置，本轮不将它们绑定。系统原生文件选择器和 macOS 原生菜单的语言另受操作系统 / 平台资源控制，不承诺随 Flutter 应用内偏好热切换。

### 文案、菜单与格式化边界

- 文案抽取包含标题、按钮、提示、校验、空状态、菜单、tooltip、语义标签及播放器启动失败页，不只迁移 `Text`。
- 「第几季 / 第几集」、文件数量、进度等组合文案通过 ARB 的参数与 ICU 复数表达；不要拼接翻译片段或把中文字符串从格式化工具带入 UI。
- 日期 / 数字在展示层显式使用当前 locale；`FileBrowserEntryDisplay` 等无 context 的展示扩展可接受 locale 或改为展示层函数，不向领域模型注入 Flutter 依赖。
- 自定义文本菜单保留现有样式、操作和启用条件，标准剪切 / 复制 / 粘贴等标签优先复用 Flutter 的本地化资源；自定义操作标签走 ARB，不维护另一份中文菜单字典。
- 简体中文和英文均完成对应文案后才宣布该模块支持双语。分期迁移中的硬编码必须登记为待办，不能以中文 fallback 或新旧文案两条分支长期保留。

### 生成与 CI

```yaml
# l10n.yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-dir: lib/l10n/generated
output-localization-file: app_localizations.dart
nullable-getter: false
```

`pubspec.yaml` 增加 SDK 依赖 `flutter_localizations` 与 `flutter.generate: true`。以上配置使用项目锁定 SDK 的生成机制，不添加已废弃的 `synthetic-package` 配置。

开发环境和 CI 明确执行 `flutter pub get` → `flutter gen-l10n` → `flutter analyze` → `flutter test` → 平台构建；生成步骤须在静态检查和测试之前。README、测试指南与构建说明同步命令，CI 从没有生成文件的干净检出也必须成功。

模板 key、占位符类型 / 元数据与译文保持一致；CI 校验缺失译文，不能只依赖生成命令成功，因为模板回退可能掩盖缺译。测试覆盖中英文输出、ICU 复数 / 参数、locale 格式化、非法偏好和系统语言回退。

## Consequences（后果）

- **正面**：系统内建文案与业务文案一致；可在应用内选择中英文或跟随系统；ICU 处理参数与复数；后续新增译文无需自建翻译引擎。
- **代价**：文案分散在多个模块，需要分期抽取；语言偏好需持久化并让共享控制器通知各视图；非 UI 的错误提示需结构化；干净检出、构建与 CI 需要本地化生成。
- **范围限制**：本轮不翻译用户媒体内容，不改变 TMDB / 字幕语言设置，不承诺系统原生界面即时切换语言。

## 实施阶段与验收

2026-10-12 已实施：

- SDK 本地化依赖、生成配置、输出目录 / 忽略规则、两个窗口的委托 / locale 接线，以及英文回退策略。
- [AppLocaleController](../../lib/l10n/app_locale_controller.dart) 的三种语言偏好、持久化、退出时已接受写入收尾与即时通知；2026-10-13 改为双视图共享实例，删除 revision、快照与启动校准。
- 设置、媒体库、文件浏览、播放、首页与应用导航的 ARB 文案，包括常用弹层、校验、空状态、控制栏与启动失败页；季集、数量使用参数 / ICU，日期 / 数字显式指定 locale。
- 标准文本菜单复用 Flutter 翻译，保留原有菜单样式与操作；后台用户错误改为 `AppFailure`，活动进度改为 `LibraryActivity`，展示时使用当前语言。
- [资源完整性检查](../../tool/check_l10n.dart)、CI 生成步骤及开发命令；不保留旧翻译 API 或中文 fallback 文案分支。日志、解析规则和字幕语言匹配中的中文不作为 UI 硬编码删除。

实施顺序（四阶段均已完成代码接入）：

1. **基础接线**：依赖、配置、生成目录 / 忽略规则、CI 和开发命令；两个 `MaterialApp` 使用同一套委托、支持语言和解析策略。接线只解决 Flutter 内建文案，不能据此宣布完整英文支持。
2. **偏好与通用组件**：接通已有设置入口，提供三种选项；持久化、重启恢复、主 / 子窗口同步与启动竞争；标准文本菜单复用 Flutter 翻译。
3. **业务抽取**：按 `settings → library → playback → app shell` 抽取，每阶段同时交付英文模板与中文译文；包含无 context 的错误 / 状态及日期、数量、季集等格式化。
4. **收尾**：搜索遗漏的硬编码与旧菜单标签，验证无兼容别名 / 双套文案路径，同步 README、架构说明和实施状态。

回归基线：

- 主窗口和播放器在中文、英文系统环境启动；不支持的系统语言回退；非法 / 缺失偏好恢复默认。
- 选择三种偏好后重启、单独关闭并重开播放器，两个窗口显示一致。
- 播放中、播放器启动中、请求替换中切换语言，不重开媒体或丢失进度；退出期间不派发新同步任务。
- 两种语言下的业务页面、播放器失败页、文本菜单、tooltip、语义标签及已有弹层；后台任务结束后的提示使用当前语言。
- 日期 / 数字、ICU 参数和复数正确，英文长文案无截断、重叠；缺译校验能拦截遗漏。
- 删除生成目录后重新生成、静态检查、测试及平台构建成功，生成物未进入 Git。

### 验证边界

偏好、共享观察、保存失败重试、ICU、locale 格式化和语言变化不重新挂载 Widget 会话有自动化回归；当前文案检查与平台构建证据统一见 [测试指南](../guides/testing.md)。完整页面布局、真实播放中切换、系统语言变化与原生界面仍需分别验收，不能把假窗口 / Widget 测试推广为平台交互已通过。

2026-10-12 首次接入的数量和验收限制保留在 [验证历史](../history/validation-2026-10.md)。当前不再使用过期 revision 防护或跨窗口快照；单引擎共享语言控制器的变更直接通知各视图。

## Alternatives（备选与否决理由）

| 备选 | 否决理由 |
| --- | --- |
| 自建 `Map<String, String>` 文案表 | 需要自己实现 locale 解析、复数、占位符与回退逻辑，且无法与 Material 内建文案打通 |
| 只补 `localizationsDelegates` 不抽文案 | 能修掉系统文案，但业务文案仍硬编码，后续抽取成本只会更高 |
| 第三方方案（如 `slang`、`easy_localization`） | 能力与官方方案重叠，且引入额外依赖与生成器；当前使用官方 SDK 本地化能力与 intl，无需第三方翻译框架 |
| 以中文为模板（`app_zh.arb` 作 template） | 本可接受，但英文模板符合 gen-l10n 默认约定、ICU 复数表达更完整，也更利于外部贡献者；本项目已存在英文需求（系统文案） |

## Revisit trigger（重估触发条件）

满足任一条即重新评估：

1. 新语言需要额外的文字方向、区域 / 脚本解析或平台资源策略；普通新增 ARB 译文按现有流程实施，无需推翻此决策；
2. 文案需求超出 ARB 表达力（例如需要按语言切换整站文案风格、或需要翻译平台对接流程）；
3. Flutter 官方本地化方案发生重大变更（如 gen-l10n 被替代）。
