# 0003 持久化：Isar 3 迁往 drift + SQLite

- **Status**: Accepted
- **Date**: 2026-10-11（初稿 2026-10-05）
- **Related**: [0001 多窗口策略](0001-multi-window-strategy.md)

## Context（背景与约束）

原实现采用 Isar 3，媒体库依赖全量加载与内存修订号，缺少版本化 schema 迁移与真实数据库测试。多窗口为每引擎各开数据库连接，需要明确的并发访问语义。

项目目前没有 Release 版本。用户确认本次替换不需要保留旧开发数据，因此取消初稿中「必须搬运旧 Isar 数据」的要求。新库与旧库使用不同文件名，不读取、转换或删除旧 Isar 文件。

## Decision（决策）

**持久化替换为 drift + 原生 SQLite，直接使用不可变领域模型与 SQL 查询订阅；本次直接建立新库，不导入旧 Isar 数据。**

必须遵守的规则：

1. 使用 drift `@UseRowClass` 直接读写不可变领域模型，删除旧 Entity、Stored 枚举和手写双重映射，不保留旧存储接口。
2. 媒体文件使用 `storageKey = sourceId:path` 的 UNIQUE 约束；元数据直接使用 TMDB ID / 季键作为主键，媒体源使用 `sourceId` 唯一键。文件和来源按业务键 upsert，保留已有行的自增 ID。
3. 生产数据库通过 `NativeDatabase.createInBackground` 在后台 isolate 执行。每个连接启用 WAL 与 `busy_timeout = 5000`，首次切换 WAL 遇到锁竞争时限时重试，首次建表在写锁内复查版本并原子提交，支持现有多引擎窗口访问同一库。
4. 类型标签和演员列表通过 `TypeConverter` 存为 JSON 文本；枚举存名称，日期存 ISO 文本以保留微秒精度。
5. 新库文件为应用文档目录下的 `mochi_player.sqlite`，schema 版本从 1 开始。后续 SQLite schema 变更必须提升版本并补迁移与测试。
6. 本次不实现 Isar 导入，不删除旧库。开发者需重新配置媒体源并扫描。
7. 扫描属性、元数据匹配、播放进度和收藏分别按字段更新，避免旧快照互相覆盖。媒体源与所属文件的删除、批量媒体写入、清空操作保持事务性。

## 实施状态

已完成：

- 六张 typed drift 表、业务唯一键与媒体文件索引；
- 领域模型直接映射、JSON 转换器与按业务字段拆分的写入接口；
- 扫描与季集导入使用真正的 drift batch，不逐行等待或返回完整行；
- SQL 列表、搜索排序、收藏聚合、续播目标和按标题范围的详情 / 队列；
- UI 查询订阅与列表分页，删除全量 `MediaLibraryCatalog` 与修订号；
- 首页只保存有限展示投影，独立播放窗口写入后通过既有事件主动使查询失效；
- 移除 Isar 依赖、注解、未使用的链接与生成物；
- 更新平台插件注册文件，SQLite 通过 sqlite3 的 native assets 打包；
- 真实 SQLite 内存测试与文件双后台连接测试；
- 初始 schema 快照与生成代码随仓库提交。

后续独立实施：

- 按 [0001](0001-multi-window-strategy.md) 实施退出协调，保证主窗口退出前完成播放器最终进度提交；当前保留多连接，单写者根据实测问题或明确收益另行评估；
- 元数据回收、TMDB 网络错误分类和凭据存储改进。

## Consequences（后果）

- **正面**：获得 SQL 查询、索引、事务与版本化 schema；真实数据库测试可在内存运行；现有多连接由 SQLite 锁与 WAL 协调。
- **负面**：需要 drift 生成代码与 SQLite native assets；初次替换后需重新配置与扫描；Windows 多引擎输入冻结仍属于独立任务。
- **边界**：跨独立连接的 drift 查询订阅不会自动同步通知，当前通过播放器回传变更键后主动失效；如需播放过程中实时同步，必须补通知协议。

## Alternatives（备选与否决理由）

| 备选 | 评价 | 结论 |
| --- | --- | --- |
| isar_community | 替换成本低，但仍需重新解决版本化迁移与数据查询结构 | 不采用 |
| 裸 sqlite3 | 少一个生成器，但需手写 SQL、行映射、迁移与订阅 | 保留备选 |
| Isar → SQLite 一次性搬运 | 能保留旧数据，但项目尚未发布，用户确认无此需求 | 本次不实施 |
| 保留可变 DTO 与内存 Catalog | 延续旧写入风险和全量缓存，增加适配层 | 不保留 |

## Revisit trigger（重估触发条件）

1. SQLite native assets 在 macOS / Windows 构建或发布中出现阻塞；
2. 多连接竞争导致实测写入错误或超时，重新评估事务、锁等待策略及数据库单写者方案；
3. 发布后需要变更 schema，必须建立版本间迁移与数据保留契约；
4. 需要在播放过程中实时同步多窗口状态时，重新评估连接与通知边界。
