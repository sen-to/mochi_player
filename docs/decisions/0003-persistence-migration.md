# 0003 持久化：Isar 3 迁往 drift + SQLite

- **Status**: Accepted
- **Date**: 2026-10-14（初稿 2026-10-05，持久化替换 2026-10-11）
- **Related**: [0001 多窗口策略](0001-multi-window-strategy.md)

## Context（背景与约束）

原实现采用 Isar 3，媒体库依赖全量加载与内存修订号，缺少版本化 schema 迁移与真实数据库测试。多窗口为每引擎各开数据库连接，需要明确的并发访问语义。

项目尚未正式发布，持久化替换不要求保留开发数据。新库与旧库使用不同文件名，不读取、转换或删除旧 Isar 文件。

## Decision（决策）

**持久化替换为 drift + 原生 SQLite，直接使用不可变领域模型与 SQL 查询订阅；直接建立新库，不导入旧 Isar 数据。**

必须遵守的规则：

1. 使用 drift `@UseRowClass` / SQL `WITH` 直接读取不可变领域模型，通过生成的 Insertable / Companion 写入；删除旧 Entity、Stored 枚举和手写双重映射，不保留旧存储接口。文件与单集表在 `media_tables.drift` 声明组合关系，让生成器处理级联订阅，其余表使用 Dart 声明。
2. 媒体文件使用 `(sourceId, path)` 的组合 UNIQUE 约束；电影 / 剧使用 TMDB ID，季使用 `(tvShowTmdbId, seasonNumber)`，集使用明确命名的 `episodeKey` 主键并另存真实 TMDB ID，媒体源直接使用 `sourceId` 主键。文件 upsert 保留已有自增 ID；派生 `storageKey` 不存数据库。
3. 生产数据库通过 `NativeDatabase.createInBackground` 在后台 isolate 执行。每个连接启用 WAL 与 `busy_timeout = 5000`，首次切换 WAL 遇到锁竞争时限时重试，首次建表在写锁内复查版本并原子提交，保留多连接安全性；2026-10-13 官方多视图迁移后生产视图共享同一后台连接，连接仅在应用退出时关闭。
4. 类型标签和演员列表通过 `TypeConverter` 存为 JSON 文本；枚举存名称，日期存 ISO 文本以保留微秒精度。
5. 新库文件为应用文档目录下的 `mochi_player.sqlite`，当前 schema 为 2。项目未发布，从开发版本 1 原子重建六表，不搬运数据；未知版本转换拒绝执行。发布后必须建立保留数据的迁移契约，不能沿用开发库重建策略。
6. 不实现 Isar 导入，不删除旧库。开发者需重新配置媒体源并扫描。
7. 扫描属性、元数据匹配、播放进度和收藏分别按字段更新，避免旧快照互相覆盖。媒体源与所属文件的删除、批量媒体写入、清空操作保持事务性。
8. 季集归属使用显式字段、外键和组合唯一约束，不依赖字符串前缀查询。媒体源删除级联删除文件；剧 / 季删除级联删除子元数据；仍被文件引用的元数据禁止删除。文件的单集键与所属剧通过组合外键保持一致。
9. 版本查询和标题收藏必须带标题类型，避免电影和电视剧相同 TMDB ID 串查。数据库写进度、续播与界面共用 `WatchProgressPolicy`。

## Consequences（后果）

- **正面**：获得 SQL 查询、索引、事务与版本化 schema；真实数据库测试可在内存运行；共享连接直接提供查询订阅通知，额外独立连接的并发由 SQLite 锁与 WAL 协调。
- **负面**：需要 drift 生成代码与 SQLite native assets；初次替换后需重新配置与扫描；Windows 官方多视图宿主的输入回归仍须独立验收。
- **边界**：生产主视图与播放器使用同一连接，进度提交直接刷新 drift 订阅；跨独立连接不自动共享通知，但当前没有回传变更键或兼容失效协议。

## Alternatives（备选与否决理由）

| 备选 | 评价 | 结论 |
| --- | --- | --- |
| isar_community | 替换成本低，但仍需重新解决版本化迁移与数据查询结构 | 不采用 |
| 裸 sqlite3 | 少一个生成器，但需手写 SQL、行映射、迁移与订阅 | 保留备选 |
| Isar → SQLite 一次性搬运 | 能保留旧数据，但发布前开发数据无需保留 | 不实施 |
| 保留可变 DTO 与内存 Catalog | 延续旧写入风险和全量缓存，增加适配层 | 不保留 |

## Revisit trigger（重估触发条件）

1. SQLite native assets 在 macOS / Windows 构建或发布中出现阻塞；
2. 多连接竞争导致实测写入错误或超时，重新评估事务、锁等待策略及数据库单写者方案；
3. 发布后需要变更 schema，必须建立版本间迁移与数据保留契约；
4. 未来引入独立进程或数据库连接时，重新评估连接所有权与订阅通知边界。
