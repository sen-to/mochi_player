# 0001 多窗口策略：官方单引擎多视图，主窗口关闭即退出应用

- **Status**: Accepted
- **Date**: 2026-10-13（初稿 2026-10-05，mini 决策补充 2026-10-14）
- **Related**: [播放引擎](0002-playback-engine.md)、[持久化](0003-persistence-migration.md)、[本地化](0004-i18n-l10n.md)、[历史原型](../history/official-single-engine-windowing.md)

## Context（背景与约束）

产品需要独立播放器窗口，同时共享媒体库、进度、主题与语言。旧多引擎插件方案需要窗口 RPC、独立状态与连接协调，增加了同步与退出成本。主窗口关闭后必须结束整个应用，不能留下播放器或后台音频。

官方多视图 API 在选型时仍属实验能力，需要固定开发通道 SDK 并承担原生适配与插件兼容成本；原型只证明选型可行，不代替业务验收。

## Decision（决策）

**采用官方单引擎多视图：一个主视图、最多一个播放器视图，共享应用状态与数据库；关闭主窗口即退出整个应用。**

### 窗口与资源规则

1. runner 只创建一个 FlutterEngine、注册一次插件；Dart 管理视图。不保留旧多引擎后端、窗口 RPC、JSON 启动兼容协议或语言快照。
2. 应用共享数据库、语言、主题和设置；窗口操作、消息宿主与播放资源按所有者管理。原生操作显式携带 viewId，不按焦点或隐式视图猜测窗口。
3. 播放器创建 / 替换 / 关闭必须串行；替换解析失败保留原播放。先释放资源、解绑视图并等待渲染帧，再销毁原生窗口。
4. 所有可拦截的主窗口关闭、平台退出和 macOS Cmd+Q 进入同一幂等退出流程：拒绝新任务，保存 / 释放播放器，收尾后台任务与偏好，关闭数据库后退出。
5. 清理必须有界，失败继续后续阶段；超时不能伪称最终进度已保存。单独关闭播放器保留主窗口与数据库。

### SDK 与发布

使用 `.fvmrc` 固定提交，团队与 CI 不跟随浮动 main。实验窗口能力由项目配置开启，不使用全局配置或单次 run 参数代替。FVM 获取预编译引擎，不要求自行编译引擎；Release 构建能力与签名、公证、正式分发分别验收。

官方适配封装在视图级窗口服务中，缺少的能力通过原生桥补充。SDK 的旧 UI 导入弃用提示暂不阻塞检查，但错误和警告仍需修复；独立 UI 包迁移单独处理。[官方迁移说明](https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui)

### 小窗：采用 mini 播放器

mini 复用播放器窗口与播放会话，延续字幕、切集及现有控制；默认置顶、允许切换，退出时恢复原尺寸、约束与置顶状态。它使用普通系统窗口层级能力，不是系统画中画，也不承诺跨所有 Spaces 或其他应用全屏空间显示。

项目需要双平台一致的媒体库播放体验。系统 PiP 会额外引入内容源、视频帧 / 字幕合成和平台控制桥接成本，因此暂不实现 PiP、双方案自动回退或视频帧出口。

## Consequences（后果）

- 减少跨窗口通信和重复状态 / 连接管理，保留独立播放器与明确退出语义。
- 固定 main SDK、internal API 和原生扩展增加维护成本；单个 UI isolate 中的同步阻塞影响所有视图。
- 实验 API 可构建不等于稳定性承诺，插件和运行时仍需逐平台验收。

## Alternatives（备选）

| 方案 | 取舍 |
| --- | --- |
| 保留多引擎插件 | 同步与退出复杂，不保留兼容 RPC |
| 取消独立播放器 | 不符合产品需求 |
| 自建原生多视图宿主、继续 stable | 需自行维护窗口协议和适配，成本高于采用官方开发通道 API |
| 改为原生播放器 | 属于播放后端决策，不与窗口迁移捆绑实施 |

## Revisit trigger（重估触发条件）

1. 官方 API 在稳定通道开放或出现不兼容变化，重新锁定 SDK 并验收。
2. 目标平台出现无法修复、阻塞主流程的插件或窗口缺陷。
3. mini 无法满足新的小窗产品需求。
4. 产品改为主窗口关闭后继续播放，必须重设计应用宿主与数据库生命周期。
